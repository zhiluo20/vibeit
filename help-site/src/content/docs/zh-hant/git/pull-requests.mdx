## 核對結果

進入生成的 PR 檢查改動。同步被拒絕或歷史分叉時，先用合適的 Git 工具或伺服器終端處理，再重試。

## 如果沒有成功

- Commit 記錄本地歷史，Push 才會發送到遠程。先確認失敗的是哪一步。
- 推送被拒絕時，檢查遠程改動和帳號權限，不要把強制推送當作常規修復方式。
- 發生衝突時，先保留副本並檢查相關檔案，再決定如何處理改動。
