## 你将完成什么

从已推送的分支发起改动提案，并识别常见同步失败原因。

## 开始前准备

- 有效的 Pro 订阅。第三方 AI 订阅和 API 额度需要单独准备。
- 能够连接本教程所用服务或下载资源的网络。
- 一个已经存在的 Git 仓库。练习时使用独立的教程仓库。

## 核对结果

进入生成的 PR 检查改动。同步被拒绝或历史分叉时，先用合适的 Git 工具或服务器终端处理，再重试。

## 如果没有成功

- Commit 记录本地历史，Push 才会发送到远程。先确认失败的是哪一步。
- 推送被拒绝时，检查远程改动和账号权限，不要把强制推送当作常规修复方式。
- 发生冲突时，先保留副本并检查相关文件，再决定如何处理改动。
